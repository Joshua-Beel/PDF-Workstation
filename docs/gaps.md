# Gaps versus the supplied feature reference

## Viewer foundation

Embedded-text Find is implemented in the source build: matching pages, highlighted/selectable excerpts, next/previous navigation, case matching, cancellation, a 500-page result cap, and literal highlights over visible supported glyph geometry. Page text can be selected in a separate dialog. Supported embedded text can also be selected directly on rendered pages: geometry covers crop offsets and cardinal glyph rotations, is requested only after visible page images load, and is capped at 20,000 characters. Pan mode keeps search highlights but disables selection. Skewed, mirrored, malformed, over-cap, no-positioned-geometry, or text-order-mismatched matches route explicitly to Page text or Find results; scanned pages normally have no embedded text. A signed installed-app check copied an exact programmatic range through the Windows clipboard; physical pointer dragging and arbitrary PDFs remain unverified. The bookmark pane supports nested entries and internal page destinations, capped at 1,000 entries; bookmark destinations carry zoom and position, and bookmark editing (add, rename, delete, move, indent, outdent, saved into a new copy) exists in the source build only, with no installed-app check and no recovery-point coverage. Reading preferences, recent files and stars persist locally, with three-launch installed-app coverage for preference retention and history clearing. Opening-password prompts support retries and cancellation; encrypted files remain read-only. Installed-app fixtures cover wrong and correct passwords, reopen, and cancel. Document properties show source metadata, current page dimensions and reported permissions without validating signatures. Native Windows printing is implemented, with signed installed-app coverage for cancellation, reopen, and one-page Microsoft Print to PDF output. Physical paper, non-Microsoft drivers, post-submission cancellation, and driver failures remain unverified. Strict app-owned annotations are current source work: sticky notes, area highlights, and supported selected-text highlights can be created, selected, edited, or deleted, and crop-hidden annotations stay editable from the Comments panel. Text highlights map a single browser selection outward to whole native geometry characters and let native rendering derive their quads; they are unavailable for cross-page, stale, unsupported, truncated, or unmapped text, including the pinned engine's astral mapping fixture. Area highlights are dragged rectangles, not text selections; native PDF rendering owns both highlight appearances. Foreign, empty, malformed, signed, encrypted, form, tagged, page-label, and article-thread annotations are explicitly unavailable; bodies do not expose through Page text or Find, and printed pages render native appearances only. Fill forms is current source work for a strict, visible, flat subset of single-line text fields, flat merged checkboxes, standard one-level same-page radio groups, and single-select choice controls. Text values are printable ASCII, button appearances remain validated source appearances, and choice fields use exact source display labels while native code keeps their private export values internal. Choice controls can be noneditable dropdowns or fully visible list boxes only; all current page plans must be unchanged, and unsupported PDFs are refused without partial output. A supported group or choice may start blank, but a selection cannot be cleared. Editable combos, multi-select or scrolling lists, radio groups outside that subset, Fill & Sign, certificates, form preparation, and general form editing remain unavailable. It saves a new copy and leaves the source session unchanged. Organize Pages can split the current edited page order into fixed-size files in a new Windows-selected folder, up to 64 outputs and 256 MiB per output, crop one or more selected physical pages from equal point insets in each page’s current displayed bounds, reset session crop edits for selected physical pages, insert every current edited page from a distinct open donor at a selected target boundary into a new copy, or replace one contiguous target range with all donor pages in a new copy. Reset crop does not remove original or inherited source crop/page boxes after reopening, and native desktop interaction remains unverified. Batch crop validates every target before one undoable change; mixed-size or rotation previews show dimensions only. The full native batch gate passed 149 tests (0 failed, 1 ignored) in 462.16 seconds, and the standalone Tauri debug/no-bundle build passed with 1,932 frontend modules (2.52 seconds frontend, 19.67 seconds native). Crop hides content and is not redaction; native desktop crop interaction, the split folder dialog, and the Insert Pages and Replace Pages save dialogs still need verification. Folder search, embedded attachments, layer toggles, tags, signatures, rulers, page-label editing, label-based jumps or export ranges, alternate page layouts, and read-aloud remain unavailable. Files currently stay open in one native worker. Organizer thumbnails are implemented, but viewer-pane thumbnails, progressive low-resolution previews, cancelable priority queues, and crash isolation remain unimplemented. The source recovery integration can journal acknowledged supported edits and offer a matching record during ordinary open, but explicit-discard and post-publication error alignment are under repair; actual process-restart, installed-app, and power-loss recovery remain unverified, and there is no unattended autosave schedule. Native page edits export through lopdf. Documents over 65,536 pages are rejected explicitly.

The source build now accepts one native dropped nonempty `.pdf` path through the existing reopen/password path. Multiple, empty, and non-PDF drops are rejected, and busy/modal drops leave open documents and edits intact. Actual Windows drag/drop interaction remains unverified.

Page text returns only visible, cropped embedded text. It permits up to 1,048,576 UTF-8 bytes per page and reports an error above that limit rather than truncating the result. Page text, Find, and on-page selection work for unencrypted PDFs and, after unlocking, with an owner password or the ordinary Copy permission; accessibility-only or unverifiable permissions are refused. A denied on-page selection reports the extraction error without directing people to unavailable Page text. OCR remains unavailable for encrypted PDFs. The bookmark pane remains capped at 1,000 entries; its returned titles together permit up to 1 MiB of UTF-8 text and error above that title-text limit rather than returning a partial list.

The default native suite passed 201 tests with 0 failures and 7 ignored in 429.62 seconds. Separate `ocr_build` build-helper integration tests passed 7 tests with 0 failures in 0.07 seconds. These are source checks, not native desktop or installed-app interaction evidence.

## Performance and compatibility

No validated 60 fps target, 10,000-page open latency, real 300-dpi scan benchmark, or multi-viewer round trip. The page geometry list is collected at open, rather than a fully lazy page-tree implementation. The Viewer uses indexed visible/current-page lookups, but its 65,536-page access-count test is not a frame-rate or memory benchmark. The Pages sidebar virtualizes its buttons, while the existing full-height viewer has no measurement establishing end-to-end navigation through a 65,536-page document. Rendered page images are virtualized separately. The native cache, undo/redo snapshots and individual print bitmaps have limits; these are not a measured total application RSS cap.

Fit page is source-only: it uses an explicit target physical page instead of following free scrolling, and its retained 10% minimum scale can prevent a full fit in an unusually small viewport.

## Remaining tools

Organization now supports rotate/delete/extract, move earlier/later or directly to a numbered position, fixed-size splitting to a new folder, equal point-inset cropping across selected physical pages using each page's current displayed bounds, resetting only selected session crop edits, insertion at a target boundary, and replacement of one contiguous target range with all current pages from a distinct open donor; each structural copy leaves source sessions unchanged. Reset crop leaves original/inherited source boxes, rotations, and annotations intact, and cannot reverse a crop that is already stored in a reopened PDF. Its 199-test/43-file frontend suite, 167-passed/0-failed/1-ignored native gate in 332.24 seconds, and successful standalone debug/no-bundle build are source evidence; native desktop and installed-app interaction remain unverified. Batch crop validates every target before one undoable change, and mixed-size or rotation previews show dimensions only. Strict app-owned sticky notes and highlights follow supported move/delete/extract/split operations, undo/redo, and Save a Copy. Combine Files, Insert Pages, and Replace Pages retain the target/first PDF's Info/XMP metadata, reject annotated or unsupported page-tree/catalog sources, cap aggregate input at 4,096 pages and serialized output at 256 MiB, and leave source sessions unchanged. Export page as image is implemented for one current edited physical page as PNG or JPEG at 72, 150, or 300 DPI. Both formats flatten the visible crop, rotation, supported annotations, and supported form appearances to white-flattened 8-bit RGB; JPEG is lossy at fixed quality 90 and carries exact JFIF density, while PNG carries rounded `pHYs` density. Neither format exports a document, OCR, editable text, vectors, or multiple pages; each has a 256 MiB encoded-output limit, and native picker and installed-app behavior remain unverified. Create a PDF from one image is implemented for one bounded PNG or JPEG source, and the bounded multi-image route accepts 1–32 ordered sources into one clean page per image. Strict new-copy routes also replace one exact supported full-page raster or one exact-length Base14 Helvetica/WinAnsi text run. These routes preserve source sessions and refuse unsupported inputs; native desktop picker interaction and installed-app behavior remain unverified. Page-label display is implemented for supported source trees; page-label editing, label-based jumps or export ranges, page-box operations, drag-reordering and extraction into separate files remain unimplemented. Signed or certified documents are rejected for edits; complex page-reference structures are rejected for relevant destructive/structural operations until preservation is implemented. See the tool documentation for exact restrictions.

General image conversion, arbitrary text/image editing, format export, searchable/document OCR in default and published builds, image enhancement, replies, author identity, foreign-annotation interchange, stamps, measurement, comparison, form preparation, Fill & Sign, certificates, password security, general sanitization and content-preserving or multi-page redaction, PDF standards, optimization, accessibility, print preview, action wizard, custom-tool, index and virtual-printer features remain unimplemented. Image-to-PDF routes normalize supported images to 8-bit RGB, composite transparency onto white, and drop ICC profiles and image metadata; they refuse animation and multi-picture content. The bounded raster-redaction route is destructive: it rasterizes every current page at fixed 150 DPI, applies marks only to one captured page, and removes searchable/editable document structures. Selected-text highlighting is limited to supported geometry and is not Acrobat-compatible annotation interchange. Disabled cards are a roadmap, not evidence of implementation.

## Distribution and verification

The installer, signed updater, and release CI are implemented. Published 0.2.0 and the signed but unpublished 0.2.6 draft have separate evidence; the 0.2.6 draft assets, signatures, notices, and five exact MPL source archives were independently checked before the privacy rewrite, but were not rebuilt or re-signed for the rewritten source tag. Hosted checks now cover a silent baseline install and manual upgrade, signed-app WebView launch, packaged-sample rendering and current-page OCR integration/completion/recognition, and clean exit. The OCR accuracy flag remains false, so correctness, general accuracy, and real-document quality remain open. Native-window visuals, real preference migration, user documents and pickers, printing, native drag/drop, updater/release behavior, and full cross-viewer checks remain unverified. The [dependency inventory](license-inventory.md) records the remaining WebView2 distribution review; the project itself is MIT-licensed (see the root `LICENSE`). Native-window desktop UI tests and a 200-file real corpus remain outstanding. Synthetic tests and manual UI checks are recorded separately in phase status. The current source build has only the bounded destructive raster-redaction route described above; it must not be treated as a general sanitization or content-preserving redaction tool. It must not be used as a document-signing, PDF/A-conformance, or general form-filling tool.
