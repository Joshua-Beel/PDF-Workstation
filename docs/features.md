# Features in detail

The full feature descriptions, moved verbatim from the README's "What works" section (only relative link paths were adjusted for this folder). The [README](../README.md#what-works) keeps a one-line summary of each.

## Reading and navigation

- **Reading:** open PDFs in tabs, scroll through pages, pan, jump to a page, zoom from 10% to 400%, fit the document width, or fit one explicitly selected current page. The source build restores each open tab's last page when switching documents; this position lasts for the session.
- **Drop to open (source build):** drop exactly one nonempty `.pdf` path onto the native window to use the existing reopen, duplicate-document, error, and password flow. Multiple files, empty paths, and non-PDF paths are rejected. Drops are blocked while an operation or dialog is active; open documents and unsaved edits stay intact. Native Windows drag/drop interaction remains unverified.
- **Pages sidebar (source build):** mounts only the rows near its viewport: `ceil(clientHeight / 96) + 12` overscan rows and up to two current or focused rows. Up/Down arrow keys, Home, and End move a roving page focus; Enter or Space opens that physical page. Full page-label text remains available in the button name and title when the fixed visual slot clips it. Sidebar scrolling does not request page renders or page-label snapshots.
- **Page labels (source build):** read supported PDF page labels beside their physical numbers in Pages, Organize pages, and the status bar. Empty, duplicate, numeric, Unicode, and whitespace labels stay as supplied text; physical page numbers remain authoritative for navigation. Stale, malformed, partial, encrypted, oversized, or unavailable snapshots fall back to physical numbers. See the [Page labels guide](tools/page-labels.md).
- **Bookmarks (source build):** browse up to 1,000 embedded bookmarks with nested indentation and jump to supported internal page destinations. The returned titles together permit up to 1 MiB of UTF-8 text; a larger result errors rather than showing a partial list. A bookmark now also carries its parsed destination (named destinations and GoTo actions included, resolved by PDFium): XYZ sets its zoom (held to 10-400%) and places the point at the window corner, Fit/FitB fit the page, FitH/FitBH fit the width at the given top, FitV/FitBV fit the height at the given left, and FitR frames the rectangle; page rotation, edit-session turns and CropBox are honoured. FitB variants use the page box, not the content bounds. Malformed or oversized values clamp or fall back to the page top. Unsupported actions stay disabled; the scroll and zoom feel in the running app is unverified. **Edit bookmarks** (source build): add a bookmark at the current page, rename, delete (with its nested bookmarks), move up or down, indent and outdent, set whether a bookmark opens expanded, with undo and redo, all from labelled buttons in the Bookmarks panel. Edits stay in the open document, mark it as having unsaved changes, and are written only into a new copy with Save a Copy (the source is never overwritten). Untouched bookmarks keep their original destinations and actions; the outline links and counts are regenerated. Up to 1,000 bookmarks and 32 levels can be edited; a signed, encrypted or malformed outline (a cycle, a shared item, a wrong item type) is refused with the reason and still opens read-only. Bookmark edits are not part of recovery points, and combining or inserting pages into a document with pending bookmark edits is refused. Deleting, extracting or splitting pages keeps the bookmarks of the kept pages: a bookmark (existing or added) whose page is not in the copy is left out and its nested bookmarks move up a level, and named destinations to removed pages are dropped; a malformed, shared or aliased outline or name tree still blocks it. Source build and unit tests with PDFium round trips only: no installed-app or arbitrary-file check.
- **Passwords (source build):** enter a PDF's opening password, retry it, or cancel. Passwords are not saved. Encrypted PDFs remain read-only, including files with an empty opening password. The signed installed app was verified with wrong-password clearing, a correct retry, reopening that required the password again, and cancellation against controlled fixtures.
- **Document properties (source build):** Ctrl+D shows embedded description metadata, original file size, current page sizes, reported permissions and signature count. Unknown values stay unknown; signatures are not validated.

## Text and search

- **Page text (source build):** open the current page's visible embedded text, select any portion or all of it, and copy with Ctrl+C. Current crop excludes hidden text. A page permits up to 1,048,576 UTF-8 bytes; larger results show an error rather than a truncated excerpt. Text reading, Find, and on-page selection work for unencrypted PDFs and, after unlocking, for an owner password or the ordinary Copy permission; accessibility-only or unverifiable permissions are refused. Reading order depends on the PDF; scanned images still need OCR.
- **On-page text selection (source build):** choose the pointer tool to select supported embedded text directly over rendered pages. The native layer maps cropped, cardinally rotated glyph bounds to the displayed image after it loads; pan mode disables selection. Pages with unsupported, malformed, over-cap, or no-positioned geometry show an explicit route to Page text instead; denied extraction permission reports the error without suggesting unavailable Page text. The viewer still virtualizes off-screen pages. The signed installed app copied an exact programmatic range through the real Windows clipboard and cleared it afterward; physical mouse dragging and arbitrary PDFs remain unverified.
- **Search (source build):** Ctrl+F searches embedded PDF text, with optional case matching, selectable excerpts, next/previous matching-page navigation, and highlights on visible pages with supported text geometry. Search follows page edits, uses the same text-extraction permission, and scans need OCR first. Results show one excerpt per matching page, up to 500 pages. The signed installed app verified six packaged-sample results, Page 2 navigation, and 15 highlight rectangles paired with native glyph geometry.

## OCR

- **Current-page OCR (in the published 0.3.1 installer):** with the bundled local English engine, choose **Scan & OCR** to recognize one current physical page into a read-only, copyable dialog. The captured document and revision must still match when text returns; canceling discards late text. It does not change the PDF, add searchable text, index content, save a file, or use a service. Encrypted PDFs are refused for OCR, including those whose text may be read. The published 0.3.1 installer (2026-10-27) packages the engine, the English model and their licence texts: the release build's own proof requires those five files in the extracted installer, and Step 1 draft verification (run 40586164144) checked the draft's assets, signatures and extracted contents without installing; the install-and-launch checks on the draft did not run OCR recognition (see [OCR in the default installer](releases.md#ocr-in-the-default-installer) and [0.3.1 (published)](releases.md#031-published)). A source build without an OCR setup leaves this tool unavailable. Installed recognition has been exercised only on packaged `welcome.pdf` page 1. Hosted run 40672496983 (2026-10-28) installed the exact published 0.3.1 installer on a fresh runner, verified the engine (Authenticode `Valid`, identity folder and embedded hash matched) and model, matched the engine smoke hash, and ran in-app current-page OCR on that page: recognized, 402 UTF-8 bytes, SHA-256 `EE7F76B4881365BBD45B38467996B9296D48752A0E2284190F9DA07E09DA2048` (the same receipt as the earlier signed 0.2.6 rehearsal artifact). Accuracy was not verified. Real-document use, general accuracy, real preference migration and native-window visuals remain unverified. See [OCR feasibility](ocr-feasibility.md).
- **Searchable OCR copy (in the published 0.3.1 installer; up to 32 pages):** with the same bundled engine and model, choose **Create searchable OCR copy** from the menu to save a clean new PDF. Every current page becomes a white-flattened 150-DPI raster with an invisible Unicode text layer (the engine's words, without control, whitespace, invisible-format or private-use characters, in the engine's reading order); editable text, vectors, forms, annotations, metadata, bookmarks, and attachments are intentionally not retained. The command leaves the source and its history unchanged and refuses unsupported, stale, protected, signed, certified, capped, timed-out, or clobbering requests without publishing a file. A source build without an OCR setup leaves this route disabled. Deterministic synthetic fixtures verify exact PDFium pixels and extracted text, including accented, typographic and non-BMP characters, in source builds; no installed build has created a searchable copy in any check, and real-scan recognition accuracy, extraction in viewers other than PDFium and multi-column reading order remain unverified.
- **Searchable OCR copy of a large document (source build only; not in any release):** for documents over 32 pages, **Create searchable OCR copy (large document)** runs OCR in the background on up to 10,000 pages and shows a progress panel with Pause and Cancel; you can keep reading. Pages are written to a partial file in the app data folder as they finish, so memory does not grow with the page count, and progress survives a pause, a closed app or a crash (Resume continues from the last saved page once the same document is open). A page the engine fails on twice keeps its image without text, a page that cannot be rendered becomes a blank page, and both are listed when the copy is saved; five failing pages in a row pause the job. Images are lossless (1-bit, gray or colour, whichever is exact); oversized pages are rendered at a lower resolution and listed. The finished file is checked page by page from disk and moved into place without overwriting anything. The PC is kept awake while a job runs. Evidence: unit tests with generated documents of up to 400 pages (pause, cancel, crash and torn-file resume, failing pages, full disk, bounded pages in memory) and one source-build run of the real engine on a generated 120-page text PDF (all pages read, 4 workers, about 105 pages per minute on one machine). Not verified: installed builds, real scanned documents, documents near 10,000 pages or 1 GiB, and keeping the viewer smooth while it renders OCR pages (rendering still shares the viewer's PDF engine). A copy that would pass 1 GiB (the largest file the app opens) pauses at the limit and offers **Save in parts**, which is also offered while running once the projected size passes 1 GiB: the job continues into further files of at most 1 GiB each, saved as `<name> (part 1 of N).pdf` and so on, with each part's page range listed when they are saved. No part is saved until every page is done; then every part is checked from disk and the names are checked to be free, and an existing file is never replaced. Saving in parts is exercised only by unit tests with a small injected size limit (60 generated pages in five parts, a resume after a torn journal mid-part-2 giving identical parts, taken part names, a damaged part refusing the whole set); no real copy over 1 GiB has been made. If the destination cannot be used when the copy is ready, **Save elsewhere** publishes the finished pages to a new location. Until the isolated render helper exists, a page whose PDFium render hangs stalls the job (and the viewer); Pause and Cancel still answer within about 2 seconds, but that render keeps running in the background.

## Printing

- **Printing:** Ctrl+P opens a Windows printer dialog for all pages, the current page, or ranges. The app sends page images with current edits, fitted to the printable area. Encrypted files are blocked. The signed installed app was verified on hosted Windows by canceling and reopening the native dialog, selecting Microsoft Print to PDF and Current page, saving a one-page Letter PDF, parsing it with the pinned PDF engine, and cleaning up every owned process and dialog. Physical paper, non-Microsoft drivers, and cancellation after a driver has accepted a job remain unverified.

## Pages and documents

- **Organizing pages:** select thumbnails or enter a page range, rotate pages, move a page earlier or later, delete pages, and extract a selection into a new PDF. The source build also adds direct Move to page, Split, Crop, **Reset crop**, **Insert pages**, and **Replace pages**. Reset crop removes only session crop edits from the selected physical pages; it leaves original or inherited PDF crop/page boxes, rotations, annotations, the source file, and recent files unchanged. Batch crop applies the same point insets to selected physical pages using each page’s current displayed bounds; mixed sizes or rotations show dimensional ranges only. Insert adds every current edited page from a distinct open donor PDF at a target boundary; Replace substitutes one contiguous target range with those donor pages in a new copy. The target PDF’s Info/XMP metadata is retained and both source tabs stay unchanged. Cropping hides content; it does not redact it.
- **Combining (source build):** open two distinct PDFs, choose their order in **Combine Files**, then save a new copy containing their current edited pages. The first PDF’s document metadata is retained; both source tabs, including unsaved edits, stay unchanged.
- **Saving:** undo and redo page edits, then use **Save a Copy**. Your original stays untouched, and the app asks before closing a document with unsaved edits. The source build limits undo/redo snapshots to 32 MiB per document, dropping the oldest history when needed.
- **Create a PDF from an image (source build):** choose one PNG or JPEG by content, then save a new one-page PDF. Letter or A4 pages use Auto, portrait, or landscape orientation and a finite 0–72 point margin; Auto makes a square image portrait. The image is contained and centered with upscaling allowed, and the source file and open tabs stay unchanged. PNG animation, JPEG multi-picture data, malformed or trailing image data, and images over the native input, dimension, decoded-size, or output limits are refused. Conversion applies EXIF orientation, composites transparency onto white, and normalizes to 8-bit RGB without retaining ICC color profiles or image metadata. See the [Create PDF from image guide](tools/create-pdf.md).
- **Create a PDF from multiple images (source build):** choose 1–32 PNG/JPEG sources, reorder or remove them, and create a clean PDF with one image per page using the same Letter/A4, orientation, margin, EXIF, white-compositing, and RGB8 policy as one-image conversion. Paths never cross the frontend boundary: native code retains verified opaque source reservations and rejects reparses, duplicate aliases, changed files, malformed content, and bounded-size violations. Choosing a different set swaps reservations only after the replacement selection fully validates; picker cancellation, creation errors, and output-picker cancellation retain the ordered draft for retry. Explicit dialog cancellation releases the reservation, and success opens only the returned clean copy while preserving all sources and existing sessions. Installed-app and release behavior remain unverified.
- **Replace a strict full-page image in a new copy (source build):** inspect the current revision for the supported flat profile, then choose an exact-size PNG or JPEG and save a clean new PDF. The route accepts only one unique full-page DeviceRGB 8-bit image with zero rotation, no non-equivalent crop, exact direct drawing, and no masks, forms, aliases, extra channels, or layout ambiguity. It applies bounded decoding, EXIF orientation, white compositing, and RGB8 normalization; picker cancellation and errors retain the revision-bound opaque target for retry. Success opens only the returned copy and preserves source bytes, history, undo, and redo. This is not arbitrary image/layout editing and has no source-session undo; installed-app and release behavior remain unverified.
- **Export page as image (source build):** save the current edited physical page as PNG or JPEG at 72, 150, or 300 DPI. Both outputs include the current crop, rotation, supported annotations, and supported form appearances as white-flattened 8-bit RGB images; they contain no editable text, OCR, vector content, or additional pages. PNG records rounded `pHYs` density metadata; JPEG is lossy, white-flattened, uses fixed quality 90, and records the selected density in JFIF. Page labels do not affect selection, and the source tab, history, and recent files stay unchanged. Encrypted, restricted, signed, certified, malformed, stale, or structurally unsupported PDFs are refused. See the [page-image export guide](tools/export-page-image.md).
- **Raster redaction (source build):** mark 1–256 rectangles on one current edited physical page and create a new PDF copy. The output rasterizes every current page at fixed 150 DPI with the same PDFium flags as the on-screen viewer (print-only content stays out and screen-only covers stay in, as tested on synthetic files), blacks the marked areas on the captured page, and opens as a clean new session while leaving the source unchanged. Rasterization deliberately removes searchable or editable text, vector content, forms, annotations, metadata, bookmarks, and attachments. See the [raster redaction guide](tools/redaction.md).

## Annotate and forms

- **Comments and highlights (current source work):** add, edit, or delete sticky notes, fixed rectangular area highlights, and selected-text highlights, including annotations hidden by a crop. Choose **Select**, select supported text on one visible page, then choose **Highlight selected text**; native geometry determines the saved multi-line appearance. They support undo/redo and Save a Copy. Area highlights are drawn rectangles; see the [Comments guide](tools/comments.md).
- **Fill forms (current source work):** choose **Fill forms** to make a new copy with changed values for a strict subset of existing flat, single-line text fields, flat checkboxes, standard same-page radio groups, and dropdowns, editable combo boxes, or single or multi-select list boxes. The source PDF stays unchanged. Text values must be printable ASCII or Latin-1 and fit the field's existing limits and appearance; button artwork stays validated. Radio and choice controls show their source option labels. They can begin blank only where the source supports that state. A dropdown or list-box selection can be cleared with its **Clear selection** button; radio groups cannot be cleared, because every supported group carries the form author's NoToggleToOff flag (one option stays selected). Signatures and unsupported forms are refused as a whole. See the [Forms guide](tools/forms.md).

## Workspace and privacy

- **Workspace:** light and dark themes and an All tools panel. The source build remembers theme, zoom, fit mode, pan mode, panel visibility, and up to 50 recent file locations with stars across launches. Clear file history removes this list without deleting PDFs. A three-launch signed installed-app check verified dark theme, 175% zoom, page fit, Select mode, panel visibility, a recent and starred packaged sample, history clearing, and preference retention after clearing. On ordinary source-build open, an exact matching active recovery record is offered for an explicit choice between its unsaved edits and the original. Actual process-restart and installed-app recovery remain unverified.

Your PDFs stay on your computer. There's no document upload service or telemetry.

## Known limits

Moved verbatim from the README's "What's still missing" section.

General image conversion beyond the strict one-image and multi-image routes, arbitrary text and image editing, OCR checked on real documents (0.3.1 includes the engine; installed use was checked only on the packaged sample, in the pre-tag signed build), signatures, form preparation, content-preserving or multi-page redaction marking, replies, author identity, and foreign-annotation interchange aren't ready yet. Raster redaction is intentionally destructive: it accepts rectangles on one captured page and rasterizes the entire output document at fixed 150 DPI, with no searchable text or editable PDF structures. Page-image export is limited to one current physical page and a white-flattened raster result; it cannot export a document, create OCR, retain editable/vector content, or preserve PNG density beyond rounded `pHYs` pixels-per-meter metadata. JPEG export is lossy at fixed quality 90 and does not offer a quality control. Create a PDF accepts one PNG or JPEG and intentionally loses ICC color profiles and image metadata while converting to an 8-bit RGB page with white transparency compositing; it does not preserve animation or multi-picture content. Fill forms does not provide Fill & Sign, certificates, handwritten signatures, editable combos, multi-select lists, radio groups outside the supported flat same-page subset, or a general form editor. Sticky notes and highlights use a strict app-owned PDF annotation format; their bodies are not added to Page text or search, and printing renders native appearances rather than bodies. Selected-text highlights need supported, untruncated geometry on one mounted page and do not promise Acrobat-equivalent reading order or coverage; scanned, malformed, capped, and unsupported text mappings cannot create them. On-page selection and search highlights are likewise limited to supported embedded text with cardinal glyph orientation; skewed, mirrored, malformed, capped, or no-positioned-geometry pages route to Page text or Find results. Scanned pages normally have no embedded text, which Page text reports explicitly. Printing remains unverified on physical paper, non-Microsoft drivers, and driver failures or cancellation after submission. Unavailable tools are disabled in the interface.

Saving currently means writing a new copy. You can't overwrite an existing file or save changes back to the original. Some page operations are also blocked on signed PDFs, forms, tagged documents, or files with annotations, attachments or open actions. The [Organize Pages guide](tools/organize-pages.md) explains those limits.

Next up is native-window verification of page-image and image-PDF save dialogs, save dialogs for Combine, Insert Pages, Replace Pages, annotations, and Fill forms, split folder selection, crop results, broader user-document flows, and in-app updates. There's also more testing to do with real documents, physical printers, and non-Microsoft drivers. The generated 98-page scan and 1,500-page text file are useful test cases, but they don't tell us how every large PDF will behave. The full priority list is in [Known gaps](gaps.md), the [page-image export guide](tools/export-page-image.md), the [Comments guide](tools/comments.md), the [Forms guide](tools/forms.md), and [development roadmap](development-roadmap.md).
