# Fill existing fields

Open a PDF and choose **Fill forms** from All tools or the quick toolbar. The dialog lists the fields that this build can safely preserve. Change a text value, checkbox, supported radio-group selection, dropdown, or list-box selection, then choose **Save filled copy**. Windows asks where to save the output; the open source PDF, its dirty state, and its undo history remain unchanged. The new file opens as a clean tab. The copy is rewritten with only the objects the document still references, so a replaced or cleared field's old appearance and objects from earlier saved revisions are not carried into it. A PDF with any object this build cannot load within its form limits is refused as a whole rather than copied without that object.

This is a small compatibility slice, not Fill & Sign. Text values accept printable ASCII only and are checked against both a field's character limit and its existing layout before the native operation runs. The native layer checks again before saving. It supports only flat, visible, single-line text fields with one widget, a validated fixed Helvetica style, a fixed supported font size, solid border, and supported gray or RGB colors. A populated text field must also have a compatible normal appearance; a blank text field can omit one only when its remaining validated style is sufficient. It also supports flat merged square checkbox fields, each with Off and one matching on state across its normal and any rollover or down appearances. Their bounded vector-only artwork cannot use fonts, images, or transforms, and the source styles remain intact rather than being replaced with a uniform check shape. The checkbox's source state name remains internal; the dialog shows only its source field name, page, and checked state.

Supported radio groups are one-level, flat, same-page groups with two through 32 options, Radio and NoToggleToOff flags, and exact matching Off plus one source option state in normal and any rollover or down appearances. Their bounded vector-only artwork cannot use fonts or images and allows only the validated centered translation; the original artwork stays intact. Labels come directly from the source option states, while the dialog keeps opaque widget IDs internal. A source group may begin blank only when its parent V is absent or Off and every child AS is Off; after a selection, a radio group cannot be cleared, because its NoToggleToOff flag says one option stays selected. The dialog offers no radio clear and native code rejects a null radio selection. The result preserves the group’s original appearances and default state, then changes only the current parent value and child appearance states. Radio groups spanning pages, shared or missing widgets, ambiguous states, radio-in-unison, signature controls, and other button groups are unavailable.

Supported choice fields are flat merged, single-widget dropdowns or list boxes with one through 32 source options. A dropdown is noneditable; a list box must show every option without scrolling. The dialog displays the exact source display labels in their original order and uses opaque option IDs, while native code alone maps a selection to the PDF's private export value. A supported choice may be blank only when its source value is absent or empty and its selected-index entry is absent or empty. Selecting an option is allowed, and **Clear selection** returns a dropdown or list box to blank: the copy then has no `/V` or `/I` entry and a regenerated blank normal appearance. Source defaults and option lists stay unchanged. The parser accepts only the validated fixed-Helvetica normal appearance and layout, then regenerates that normal appearance only for a changed choice. Editable combos, multi-select lists, scrollable lists, unknown styles, and ambiguous display/export or value/index mappings are unavailable.

Unsupported fields, actions, signatures, XFA, encryption, unknown appearance/layout content, non-ASCII input, overflow, or an edited page plan make the whole form unavailable or reject the attempted copy. There is no partial fill.

The original document's crop and rotation are preserved. A crop can therefore hide or clip a listed source field: it remains fillable, but this tool does not expand the crop, remove the field, or promise that the saved value is visible on the cropped page or printout.

The form has at most 256 logical fields and 256 page widgets together. Radio and choice options share a 256-option total; radio groups have two through 32 options and choice fields have one through 32. A text value is limited to 4 KiB and all field names, option labels, exports, and values to 1 MiB; the native layer also bounds source parsing, appearance decoding, and serialized output. These are compatibility and output guards, not a memory-use claim.

There is no in-place form editing, form preparation, certificate workflow, handwriting, signature placement, author identity, editable-combo or multi-select-list editing, radio-button editing outside this strict subset, or general Acrobat form support. Canceling the native save dialog or receiving a native error keeps the dialog's entries so they can be corrected or retried.

The mixed-field source gate previously passed 151 frontend/release tests and 123 native tests with one ignored manual probe, the production frontend build, and a standalone Tauri Windows debug/no-bundle build. The radio UI update passed the 152-test frontend suite, the focused native radio gate passed 6 tests, and the full native gate passed 129 tests with one ignored manual probe in 330.47 seconds. The choice UI update passed the 153-test frontend suite and production frontend build, its focused native gate passed 8 tests, and its full native gate passed 137 tests with one ignored manual probe in 346.99 seconds. The standalone Tauri Windows debug/no-bundle build passed with 1,931 frontend modules in 3.10 seconds and native compilation in 19.25 seconds. Focused UI tests and a mocked local-browser harness cover source labels, changed-only tagged choice patches, blank choices, cancellation/error draft retention, stale/busy guards, and clean output-tab activation without changing a dirty source. Native save/reopen validation is covered; Windows save-dialog, installed-app, and broader cross-viewer evidence remain separate. Existing native coverage checks source labels and opaque option IDs, supported blank groups, group-state switching, retained raw appearances/defaults, crop/rotation, reopen and immutable print snapshot bitmaps, corpus source preservation, and receiver/ownership guards. Independent pypdf inspection confirms the supplied choice fields' canonical `/V` and `/I`, option ordering, defaults, styles, and crops; Poppler found 8,562 blue pixels in a new selected list row, none in the prior output row, 1,313 changed dropdown pixels, 27,091 changed list pixels, and none outside the affected controls. The supplied radio compatibility case also had 267 new-choice dark pixels, none in the old choice, 685 changed pixels, and none outside affected widgets. This remains evidence for a strict subset, not broad cross-viewer form compatibility.
