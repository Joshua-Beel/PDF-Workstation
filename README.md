# PDF Workstation

A Windows PDF app being built as an alternative to Acrobat, with a familiar layout and tools that work locally. PDF Workstation is the working name for now.

You can already read PDFs, rearrange pages, and save your changes to a new file. There's still plenty to build before it can replace Acrobat for everyday work.

## Install

PDF Workstation is free, open-source software under the [MIT License](LICENSE).

Download the Windows setup file from the [latest release](https://github.com/Joshua-Beel/Smacrobat/releases/latest). The installer includes the PDF engine. It does not include Microsoft's WebView2 Runtime: on a machine without WebView2, the installer is configured to download it, so that install needs network access once. Installing without WebView2 has not been exercised. Once installed, open a file or choose **Explore a sample PDF** to try it out.

For updates, use **Menu > Check for updates**. The app shows what's new and lets you choose when to install. Save any edited documents first; the app won't install an update while you have unsaved changes.

Version 0.2.0 is the current published release and has a signed update package, but no Windows publisher signature. The signed, unpublished 0.2.6 draft was built before the privacy rewrite; the rewritten [`v0.2.6` tag](https://github.com/Joshua-Beel/Smacrobat/commit/8cf90166623857dddd3854ce769549da55f6f5c4) now records the cleaned source history. Its installer, updater assets, bundled resources, and three publisher signatures were independently checked. Hosted checks verify a silent/manual upgrade and the signed app’s WebView DOM, packaged-sample render, current-page OCR, process-bound Open picker, text selection through the real Windows clipboard, search geometry, password flow, three-launch preference/history persistence, native print cancellation and reopen, and one-page Microsoft Print to PDF output. These checks use controlled packaged fixtures and prove the exercised flows, not arbitrary-document compatibility, physical paper output, non-Microsoft printer drivers, native-window visuals, native drag/drop, or in-app updater behavior. See [Releases and signing](docs/releases.md).

## What works

- **Reading:** open PDFs in tabs, scroll through pages, pan, jump to a page, zoom from 10% to 400%, fit the document width, or fit one explicitly selected current page. The source build restores each open tab's last page when switching documents; this position lasts for the session.
- **Drop to open (source build):** drop exactly one nonempty `.pdf` path onto the native window to use the existing reopen, duplicate-document, error, and password flow. Multiple files, empty paths, and non-PDF paths are rejected. Drops are blocked while an operation or dialog is active; open documents and unsaved edits stay intact. Native Windows drag/drop interaction remains unverified.
- **Pages sidebar (source build):** mounts only the rows near its viewport: `ceil(clientHeight / 96) + 12` overscan rows and up to two current or focused rows. Up/Down arrow keys, Home, and End move a roving page focus; Enter or Space opens that physical page. Full page-label text remains available in the button name and title when the fixed visual slot clips it. Sidebar scrolling does not request page renders or page-label snapshots.
- **Page labels (source build):** read supported PDF page labels beside their physical numbers in Pages, Organize pages, and the status bar. Empty, duplicate, numeric, Unicode, and whitespace labels stay as supplied text; physical page numbers remain authoritative for navigation. Stale, malformed, partial, encrypted, oversized, or unavailable snapshots fall back to physical numbers. See the [Page labels guide](docs/tools/page-labels.md).
- **Create a PDF from an image (source build):** choose one PNG or JPEG by content, then save a new one-page PDF. Letter or A4 pages use Auto, portrait, or landscape orientation and a finite 0–72 point margin; Auto makes a square image portrait. The image is contained and centered with upscaling allowed, and the source file and open tabs stay unchanged. PNG animation, JPEG multi-picture data, malformed or trailing image data, and images over the native input, dimension, decoded-size, or output limits are refused. Conversion applies EXIF orientation, composites transparency onto white, and normalizes to 8-bit RGB without retaining ICC color profiles or image metadata. See the [Create PDF from image guide](docs/tools/create-pdf.md).
- **Create a PDF from multiple images (source build):** choose 1–32 PNG/JPEG sources, reorder or remove them, and create a clean PDF with one image per page using the same Letter/A4, orientation, margin, EXIF, white-compositing, and RGB8 policy as one-image conversion. Paths never cross the frontend boundary: native code retains verified opaque source reservations and rejects reparses, duplicate aliases, changed files, malformed content, and bounded-size violations. Choosing a different set swaps reservations only after the replacement selection fully validates; picker cancellation, creation errors, and output-picker cancellation retain the ordered draft for retry. Explicit dialog cancellation releases the reservation, and success opens only the returned clean copy while preserving all sources and existing sessions. Installed-app and release behavior remain unverified.
- **Replace a strict full-page image in a new copy (source build):** inspect the current revision for the supported flat profile, then choose an exact-size PNG or JPEG and save a clean new PDF. The route accepts only one unique full-page DeviceRGB 8-bit image with zero rotation, no non-equivalent crop, exact direct drawing, and no masks, forms, aliases, extra channels, or layout ambiguity. It applies bounded decoding, EXIF orientation, white compositing, and RGB8 normalization; picker cancellation and errors retain the revision-bound opaque target for retry. Success opens only the returned copy and preserves source bytes, history, undo, and redo. This is not arbitrary image/layout editing and has no source-session undo; installed-app and release behavior remain unverified.
- **Export page as image (source build):** save the current edited physical page as PNG or JPEG at 72, 150, or 300 DPI. Both outputs include the current crop, rotation, supported annotations, and supported form appearances as white-flattened 8-bit RGB images; they contain no editable text, OCR, vector content, or additional pages. PNG records rounded `pHYs` density metadata; JPEG is lossy, white-flattened, uses fixed quality 90, and records the selected density in JFIF. Page labels do not affect selection, and the source tab, history, and recent files stay unchanged. Encrypted, restricted, signed, certified, malformed, stale, or structurally unsupported PDFs are refused. See the [page-image export guide](docs/tools/export-page-image.md).
- **Raster redaction (source build):** mark 1–256 rectangles on one current edited physical page and create a new PDF copy. The output rasterizes every current page at fixed 150 DPI, blacks the marked areas on the captured page, and opens as a clean new session while leaving the source unchanged. Rasterization deliberately removes searchable or editable text, vector content, forms, annotations, metadata, bookmarks, and attachments. See the [raster redaction guide](docs/tools/redaction.md).
- **Passwords (source build):** enter a PDF's opening password, retry it, or cancel. Passwords are not saved. Encrypted PDFs remain read-only, including files with an empty opening password. The signed installed app was verified with wrong-password clearing, a correct retry, reopening that required the password again, and cancellation against controlled fixtures.
- **Document properties (source build):** Ctrl+D shows embedded description metadata, original file size, current page sizes, reported permissions and signature count. Unknown values stay unknown; signatures are not validated.
- **Printing:** Ctrl+P opens a Windows printer dialog for all pages, the current page, or ranges. The app sends page images with current edits, fitted to the printable area. Encrypted files are blocked. The signed installed app was verified on hosted Windows by canceling and reopening the native dialog, selecting Microsoft Print to PDF and Current page, saving a one-page Letter PDF, parsing it with the pinned PDF engine, and cleaning up every owned process and dialog. Physical paper, non-Microsoft drivers, and cancellation after a driver has accepted a job remain unverified.
- **Page text (source build):** open the current page's visible embedded text, select any portion or all of it, and copy with Ctrl+C. Current crop excludes hidden text. A page permits up to 1,048,576 UTF-8 bytes; larger results show an error rather than a truncated excerpt. Text reading, Find, and on-page selection work for unencrypted PDFs and, after unlocking, for an owner password or the ordinary Copy permission; accessibility-only or unverifiable permissions are refused. Reading order depends on the PDF; scanned images still need OCR.
- **Current-page OCR (opt-in source build):** when built with a verified local English engine, choose **Scan & OCR** to recognize one current physical page into a read-only, copyable dialog. The captured document and revision must still match when text returns; canceling discards late text. It does not change the PDF, add searchable text, index content, save a file, or use a service. Encrypted PDFs are refused for OCR, including those whose text may be read. Default builds and published releases leave this tool unavailable. The exact signed opt-in 0.2.6 artifact, hosted silent installer upgrade, direct installed-engine CLI smoke, signed-app WebView DOM/native OCR capability, and signed-app current-page OCR integration, completion, and recognition for packaged `welcome.pdf` page 1 are verified. That flow returned a 402-byte UTF-8 receipt with SHA-256 `EE7F76B4881365BBD45B38467996B9296D48752A0E2284190F9DA07E09DA2048`; accuracy was not verified. Real-document use, general accuracy, real preference migration, native-window visuals, in-app updater, and release behavior remain unverified. See [OCR feasibility](docs/ocr-feasibility.md).
- **Searchable OCR copy (opt-in source build):** when the same verified local English engine and model are available, choose **Create searchable OCR copy** from the menu to save a clean new PDF. Every current page becomes a white-flattened 150-DPI raster with invisible printable-ASCII text; editable text, vectors, forms, annotations, metadata, bookmarks, and attachments are intentionally not retained. The command leaves the source and its history unchanged and refuses unsupported, stale, protected, signed, certified, capped, timed-out, or clobbering requests without publishing a file. Default builds and published releases leave this route disabled. Deterministic synthetic fixtures verify exact PDFium pixels and extracted text; real-scan recognition accuracy, general Unicode/layout support, native installed interaction, and release behavior remain unverified.
- **On-page text selection (source build):** choose the pointer tool to select supported embedded text directly over rendered pages. The native layer maps cropped, cardinally rotated glyph bounds to the displayed image after it loads; pan mode disables selection. Pages with unsupported, malformed, over-cap, or no-positioned geometry show an explicit route to Page text instead; denied extraction permission reports the error without suggesting unavailable Page text. The viewer still virtualizes off-screen pages. The signed installed app copied an exact programmatic range through the real Windows clipboard and cleared it afterward; physical mouse dragging and arbitrary PDFs remain unverified.
- **Bookmarks (source build):** browse up to 1,000 embedded bookmarks with nested indentation and jump to supported internal page destinations. The returned titles together permit up to 1 MiB of UTF-8 text; a larger result errors rather than showing a partial list. Unsupported actions stay disabled; destination zoom/position and bookmark editing are not implemented.
- **Search (source build):** Ctrl+F searches embedded PDF text, with optional case matching, selectable excerpts, next/previous matching-page navigation, and highlights on visible pages with supported text geometry. Search follows page edits, uses the same text-extraction permission, and scans need OCR first. Results show one excerpt per matching page, up to 500 pages. The signed installed app verified six packaged-sample results, Page 2 navigation, and 15 highlight rectangles paired with native glyph geometry.
- **Comments and highlights (current source work):** add, edit, or delete sticky notes, fixed rectangular area highlights, and selected-text highlights, including annotations hidden by a crop. Choose **Select**, select supported text on one visible page, then choose **Highlight selected text**; native geometry determines the saved multi-line appearance. They support undo/redo and Save a Copy. Area highlights are drawn rectangles; see the [Comments guide](docs/tools/comments.md).
- **Fill forms (current source work):** choose **Fill forms** to make a new copy with changed values for a strict subset of existing flat, single-line text fields, flat checkboxes, standard same-page radio groups, and single-select dropdowns or list boxes. The source PDF stays unchanged. Text values must be printable ASCII and fit the field's existing limits and appearance; button artwork stays validated. Radio and choice controls show their source option labels. They can begin blank only where the source supports that state. A dropdown or list-box selection can be cleared with its **Clear selection** button; radio groups cannot be cleared, because every supported group carries the form author's NoToggleToOff flag (one option stays selected). Signatures and unsupported forms are refused as a whole. See the [Forms guide](docs/tools/forms.md).
- **Combining (source build):** open two distinct PDFs, choose their order in **Combine Files**, then save a new copy containing their current edited pages. The first PDF’s document metadata is retained; both source tabs, including unsaved edits, stay unchanged.
- **Organizing pages:** select thumbnails or enter a page range, rotate pages, move a page earlier or later, delete pages, and extract a selection into a new PDF. The source build also adds direct Move to page, Split, Crop, **Reset crop**, **Insert pages**, and **Replace pages**. Reset crop removes only session crop edits from the selected physical pages; it leaves original or inherited PDF crop/page boxes, rotations, annotations, the source file, and recent files unchanged. Batch crop applies the same point insets to selected physical pages using each page’s current displayed bounds; mixed sizes or rotations show dimensional ranges only. Insert adds every current edited page from a distinct open donor PDF at a target boundary; Replace substitutes one contiguous target range with those donor pages in a new copy. The target PDF’s Info/XMP metadata is retained and both source tabs stay unchanged. Cropping hides content; it does not redact it.
- **Saving:** undo and redo page edits, then use **Save a Copy**. Your original stays untouched, and the app asks before closing a document with unsaved edits. The source build limits undo/redo snapshots to 32 MiB per document, dropping the oldest history when needed.
- **Workspace:** light and dark themes and an All tools panel. The source build remembers theme, zoom, fit mode, pan mode, panel visibility, and up to 50 recent file locations with stars across launches. Clear file history removes this list without deleting PDFs. A three-launch signed installed-app check verified dark theme, 175% zoom, page fit, Select mode, panel visibility, a recent and starred packaged sample, history clearing, and preference retention after clearing. On ordinary source-build open, an exact matching active recovery record is offered for an explicit choice between its unsaved edits and the original. Actual process-restart and installed-app recovery remain unverified.

Your PDFs stay on your computer. There's no document upload service or telemetry.

## What's still missing

General image conversion beyond the strict one-image and multi-image routes, arbitrary text and image editing, searchable/document OCR in default and published releases, signatures, form preparation, content-preserving or multi-page redaction marking, replies, author identity, and foreign-annotation interchange aren't ready yet. Raster redaction is intentionally destructive: it accepts rectangles on one captured page and rasterizes the entire output document at fixed 150 DPI, with no searchable text or editable PDF structures. Page-image export is limited to one current physical page and a white-flattened raster result; it cannot export a document, create OCR, retain editable/vector content, or preserve PNG density beyond rounded `pHYs` pixels-per-meter metadata. JPEG export is lossy at fixed quality 90 and does not offer a quality control. Create a PDF accepts one PNG or JPEG and intentionally loses ICC color profiles and image metadata while converting to an 8-bit RGB page with white transparency compositing; it does not preserve animation or multi-picture content. Fill forms does not provide Fill & Sign, certificates, handwritten signatures, editable combos, multi-select lists, radio groups outside the supported flat same-page subset, or a general form editor. Sticky notes and highlights use a strict app-owned PDF annotation format; their bodies are not added to Page text or search, and printing renders native appearances rather than bodies. Selected-text highlights need supported, untruncated geometry on one mounted page and do not promise Acrobat-equivalent reading order or coverage; scanned, malformed, capped, and unsupported text mappings cannot create them. On-page selection and search highlights are likewise limited to supported embedded text with cardinal glyph orientation; skewed, mirrored, malformed, capped, or no-positioned-geometry pages route to Page text or Find results. Scanned pages normally have no embedded text, which Page text reports explicitly. Printing remains unverified on physical paper, non-Microsoft drivers, and driver failures or cancellation after submission. Unavailable tools are disabled in the interface.

Saving currently means writing a new copy. You can't overwrite an existing file or save changes back to the original. Some page operations are also blocked on signed PDFs, forms, tagged documents, or files with bookmarks and annotations. The [Organize Pages guide](docs/tools/organize-pages.md) explains those limits.

Next up is native-window verification of page-image and image-PDF save dialogs, save dialogs for Combine, Insert Pages, Replace Pages, annotations, and Fill forms, split folder selection, crop results, broader user-document flows, and in-app updates. There's also more testing to do with real documents, physical printers, and non-Microsoft drivers. The generated 98-page scan and 1,500-page text file are useful test cases, but they don't tell us how every large PDF will behave. The full priority list is in [Known gaps](docs/gaps.md), the [page-image export guide](docs/tools/export-page-image.md), the [Comments guide](docs/tools/comments.md), the [Forms guide](docs/tools/forms.md), and [development roadmap](docs/development-roadmap.md).

## Run from source

You'll need Windows, Node.js, Rust with the MSVC toolchain, Visual Studio C++ build tools, and WebView2. If you've just installed Rust, open a new terminal so `cargo` is available.

From the project folder, run these commands in PowerShell:

```powershell
npm ci
npm run fixtures
./scripts/setup-pdfium.ps1
npm run tauri -- dev
```

To build a standalone development executable:

```powershell
npm run tauri -- build --debug --no-bundle
```

You'll find it at `src-tauri/target/debug/pdf-workstation.exe`. Keep the `resources` folder beside it. This build runs without a development server.

To run the tests:

```powershell
cargo fetch --locked --target x86_64-pc-windows-msvc --manifest-path src-tauri/Cargo.toml
npm test
cargo test --locked --manifest-path src-tauri/Cargo.toml
```

To build an installer, see [Releases and signing](docs/releases.md). That guide covers signing prerequisites, GitHub Actions configuration, and publishing updates.

## Under the hood

The app uses Tauri 2, React 18, TypeScript, and CSS Modules. Rust handles PDF work: PDFium renders pages on a dedicated thread, and lopdf writes edited copies. The viewer renders pages near the viewport and uses a native cache with a 512 MiB budget that accounts for both PNG data and estimated decoded pixels.

An open document keeps a snapshot of its original bytes. Before saving, the app checks that PDFium can open the output and that the page count is right, then writes a new file without replacing an existing one.

For more background, see the [architecture notes](docs/decisions.md) and [PDFium documentation](https://docs.rs/pdfium-render/0.9.4/pdfium_render/). The interface follows the [current Acrobat workspace](https://helpx.adobe.com/acrobat/desktop/get-started/learn-the-basics/workspace.html).
